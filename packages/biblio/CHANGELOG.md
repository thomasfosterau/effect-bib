# @thomasfosterau/biblio

## 1.0.0

### Major Changes

- [#130](https://github.com/thomasfosterau/effect-bib/pull/130) [`7aa8ed9`](https://github.com/thomasfosterau/effect-bib/commit/7aa8ed9af476a1630983d6d1d32d7d62706e2136) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `parseBibtex` now reads BibLaTeX's field semantics as Pandoc does. Several fields of the records it produces change, so this is a breaking change for anyone who stores those records.

  What changes:

  - **List fields.**
    - `publisher`, `location` / `address`, `institution` and `organization` split at each top-level `and` and join with `; `: `Routledge and Kegan Paul` → `Routledge; Kegan Paul`.
    - The `publisher` is now every one of `school`, `institution`, `organization`, `howpublished` (unless it is a link) and `publisher` present, in that order, joined with `; `. It used to be the first present of `publisher`, `institution`, `school`, `organization`.
  - **Multi-volume works.**
    - A `@book` (or any uncontained entry) with a `maintitle` now has the `maintitle` as its `title` and its own title as the new CSL `volume-title`. It used to keep its own `title` and put the `maintitle` in `collection-title`.
    - A contained entry (`@inbook`, `@incollection`, `@inproceedings`, `@inreference`, …) with a `maintitle` has the `maintitle` as its `container-title` and its `booktitle` as the `volume-title`.
    - `collection-title` is now the `series` alone.
    - The container of an uncontained entry is its journal only; a `booktitle` on, say, a `@misc` now stays in `extra` as `tex.booktitle`.
    - `volume` and `part` read as `7.2`.
  - **Localisation keys** are spelled out:
    - `type` patent keys: `patentus` → `U.S. patent`, `patreqfr` → `French patent request`, …;
    - `pubstate`: `inpress` → `in press`, `inpreparation` → `in preparation`, …;
    - `series`: `newseries` → `new series`, and a bare number such as `3` → `3rd series`.
  - **Language.**
    - The legacy `hyphenation` field (an alias of `langid`) sets the `language`.
    - A `langidopts` `variant` sets a Babel language's region: `english` with `variant=british` → `en-GB`.
  - **LaTeX.** `\hyphen` decodes to `-`. `\mkbibquote` quotes its argument, as `\enquote` does, and `\mkbibemph` is italic under the `bibtexMarkup` option.

  `toBibtex` writes a record with a `volume-title` back as BibLaTeX's `maintitle` / `title` (or, in a contained entry, `maintitle` / `booktitle`).

  **Migration.** The `BiblioRecord` schema is unchanged; only the values `parseBibtex` produces from these fields change. Records already stored keep their old values: an old multi-volume book has `collection-title` set to its `maintitle` and no `volume-title`, and an old publisher list reads `X and Y`. To bring stored BibTeX imports in line, re-ingest them from their source `.bib`, or rewrite those fields. Code that reads `collection-title` as the multi-volume work should read `title` and `volume-title` (uncontained) or `container-title` (contained) instead.

- [#97](https://github.com/thomasfosterau/effect-bib/pull/97) [`df646d4`](https://github.com/thomasfosterau/effect-bib/commit/df646d40fbdb6cd1ce8b73aa6a7f818f642ac773) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `BiblioRecord` gains citation keys and the full CSL 1.0.2 variable set, and the file parsers gain a lenient mode, caller-set limits and source positions.

  **Record (wire shape).** Every new member is optional, so a record persisted by 0.x still decodes; `fromCslJson(toCslJson(record))` moves the CSL variables a 0.x record kept in `extra` into their typed slots.

  - The CSL-JSON item `id` (`string | number`), `citation-key` and `categories`.
  - Every CSL 1.0.2 standard variable (`title-short`, `container-title-short`, `genre`, `medium`, `status`, `event-title`, `event-place`, `archive`, `archive_location`, `call-number`, `keyword`, `number-of-pages`, `collection-number`, `version`, `jurisdiction`, …), all 26 name variables (`collection-editor`, `director`, `interviewer`, `illustrator`, `recipient`, `reviewed-author`, `original-author`, `executive-producer`, `series-creator`, …) and the `available-date` date variable. The citation-time variables (`citation-number`, `first-reference-note-number`, `locator`, `year-suffix`) and `custom` stay in `extra`.
  - Validated `Pmid`, `Pmcid` and `Arxiv` brands with `decodePmid`, `decodePmcid` and `decodeArxiv`, and the matching `identifiers.pmid` / `pmcid` / `arxiv` slots. `fromCslJson` reads them from `PMID`, `PMCID` and an `arXiv:` `number` or arxiv.org `URL`, and `toCslJson` writes them back. A `PMID` / `PMCID` that does not validate is dropped, like a bad ISBN.
  - `fromCslJson` reads the legacy aliases `event`, `journalAbbreviation` and `shortTitle` into `event-title`, `container-title-short` and `title-short` when those are absent, and takes optional `RecordLimits` (`maxFieldLength`, `maxAuthors`). `sanitiseText` and `readCslNameArray` take an optional bound.

  **Parsing.** `parseBibliographicFile`, `parseBibtex`, `parseZoteroJson`, `parseCsv` and `parseRis` take optional `ParseOptions`:

  - `mode: "lenient"` keeps every entry without requiring a title or an ISBN or DOI, which a document's bibliography needs. CSL-JSON items are then read in full with `fromCslJson`. The default `"import"` mode keeps the import policy.
  - `maxRecords`, `maxInputLength`, `maxFieldLength` and `maxAuthors` default to today's constants.
  - Breaking: input over the input cap now yields one `{ outcome: "skipped", reason: "too-large" }` instead of `[]`, and entries past the record cap yield one trailing `"truncated"` outcome. Each parser now checks the input cap, not only `parseBibliographicFile`.
  - An entry's key (a BibTeX key, an RIS `ID`, a CSV `key` / `citation key` / `id` column, a CSL-JSON `id` / `citation-key`) is the record's `id` and `citation-key`.
  - BibTeX, RIS and CSV outcomes carry the entry's `position` (`{ offset, line, column }`).
  - `parseBibtex` puts the CSL variables it used to keep in `extra` (`title-short`, `genre`, `keyword`, `event-title`, …) into their typed slots, and an `arxiv` / `pubmed` eprint, `pmid` and `pmcid` into `identifiers`. An eprint or `pmid` that does not validate stays in `extra` as `tex.<field>`.

  **Rich text and dates.** Text variables may carry CSL-JSON's rich-text markup. `parseCslMarkup`, `toCslMarkup` and `stripCslMarkup` read it, write it back and strip it, and `RichText` gains a `NoCase` node (`noCase`). The built-in styles render the markup and sort and dedup on its plain text (`richField` reads markup, the new `plainField` strips it). `issuedYearText` renders a date range's years (`2001–2003`) and a `literal` date. `yearOf` falls back to the year in a `raw` date, and `endYearOf` returns a range's last year.

- [#129](https://github.com/thomasfosterau/effect-bib/pull/129) [`0711e39`](https://github.com/thomasfosterau/effect-bib/commit/0711e39ea10359370553117e064d7eeac60c1f69) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - BibLaTeX dates beyond EDTF level 0 now read as dates instead of a `literal`:

  - **Era years** are read with ISO 8601 / EDTF astronomical numbering and written as CSL counts BC years. `-0379` is 380 BC, stored as `-380`; `0000` is 1 BC, stored as `-1`. This matches Pandoc.
  - **A time of day** (`2001-01-03T17:07:34+05:00`) is dropped, and the date is kept.
  - **An open start** (`../2000`, `/1034`) becomes a range whose start is `0`, as Pandoc writes it, with the text kept in `raw`.
  - **Unspecified digits** (`199X`, `19XX`, `1999-XX`, `1999-01-XX`) become the date with the unspecified parts left out (unspecified year digits as zeros) and `circa: true`.

  EDTF level 2 quarters (`2002-33`) stay a `literal`.

- [`de4c12d`](https://github.com/thomasfosterau/effect-bib/commit/de4c12dd8b616b3e88b9a202662d0b31e466b63b) Thanks [@claude](https://github.com/claude)! - `parseBibtex` reads BibLaTeX's extended name format (biber's `\DeclareNameFormat` keys): a name such as `family=Rabble, given=Richard, prefix=von, useprefix=true` gives `{ family: "Rabble", given: "Richard", "non-dropping-particle": "von" }`. It reads the `family`, `given`, `prefix` and `suffix` parts, with braces protecting a value. A per-name `useprefix` overrides the entry's. Other keys, such as `given-i`, are ignored.   A family name that opens with a braced particle ending in a hyphen or an apostrophe (`{al-}Hasan`, `{d'}Alembert`) now gives that particle as the non-dropping particle, as biber and Pandoc read it. Before this change the particle was read as part of the family name.

- [#116](https://github.com/thomasfosterau/effect-bib/pull/116) [`eb057a3`](https://github.com/thomasfosterau/effect-bib/commit/eb057a3c41b8999ffaefa920a3b97b1cfe656e2e) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `BiblioLookup.byUrl(url)` and `lookupWebPage(client, url, options?)` fetch a publisher's page and read its embedded citation metadata with `readEmbeddedMetadata`, returning `Option<EmbeddedMetadata>` (`None` on a 404). The URL comes from the caller, so the fetch runs under a request policy built into the library. It accepts only `http(s)` URLs with no credentials and the default port. It refuses private, loopback, link-local (cloud metadata), unique-local, reserved and local-network hosts. It re-checks every redirect and follows each one by hand, at most five deep. It bounds the whole exchange, body included, to ten seconds and `MAX_INPUT_LENGTH` bytes, and it accepts only an HTML content type. A refused URL fails with the new `RefusedUrl { url, reason }` error, which joins `LookupError`. `LookupSource` gains `"web"`. The new `resolveAddresses` option on `BiblioLookupOptions` checks every address a host resolves to. Without it, host names are checked only as written, so a name that resolves to a private address is still fetched; a Worker cannot resolve DNS.

  `byDoiCsl` / `lookupDoiCsl` now run on the same policy. Their registration-agency redirect allow-list is unchanged. They gain the same time and size bounds, and they apply `resolveAddresses` to redirect hosts (`lookupDoiCsl` takes it as a new optional third argument).

  A hand-written implementation of the `BiblioLookup` service must add `byUrl`. Code that switches exhaustively over `LookupError` or `LookupSource` must handle the new members.

- [#88](https://github.com/thomasfosterau/effect-bib/pull/88) [`d98a8fc`](https://github.com/thomasfosterau/effect-bib/commit/d98a8fc12a374537d568d6b4e939282e3ad786c7) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Upstream and file-import values are parsed with Effect Schema decoders instead of hand-rolled type checks; the decoded output is unchanged. Two fixes come with it: a type, style or reference-class lookup keyed by an inherited object key (`constructor`, `toString`, …) now falls back to the default instead of returning a function (`getStyle("toString")` is `undefined`; a Crossref / OpenAlex / RIS type of `"constructor"` maps to the fallback type). `isbnForms` now names its return type, `IsbnForms`, and `builtInStyles` is typed as its two entries (`apa`, `vancouver`) rather than an open string record; look a style up by arbitrary id with `getStyle`.

- [`922ee53`](https://github.com/thomasfosterau/effect-bib/commit/922ee534e6c26ba297857e455feec4863ec4df68) Thanks [@claude](https://github.com/claude)! - A BibLaTeX list field (`publisher`, `location` / `address`, `institution`, `organization`) is now clamped and charged to the decoding budget once, as a whole, before it is split. At most `maxAuthors` items are kept, and the joined text is clamped to the field length. The split is a single linear pass. Before this change a huge list field was split before any bound applied, and long runs of blanks could make the separator pattern backtrack quadratically.
