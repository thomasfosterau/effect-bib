# @thomasfosterau/biblio

## 1.0.0

### Major Changes

- [#97](https://github.com/thomasfosterau/effect-bib/pull/97) [`df646d4`](https://github.com/thomasfosterau/effect-bib/commit/df646d40fbdb6cd1ce8b73aa6a7f818f642ac773) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `BiblioRecord` gains citation keys and the full CSL 1.0.2 variable set, and the file parsers gain a lenient mode, caller-set limits and source positions.

  **Record (wire shape).** Every new member is optional, so a record persisted by 0.x still decodes; `fromCslJson(toCslJson(record))` moves the CSL variables a 0.x record kept in `extra` into their typed slots.

  - The CSL-JSON item `id` (`string | number`), `citation-key` and `categories`.
  - Every CSL 1.0.2 standard variable (`title-short`, `container-title-short`, `genre`, `medium`, `status`, `event-title`, `event-place`, `archive`, `archive_location`, `call-number`, `keyword`, `number-of-pages`, `collection-number`, `version`, `jurisdiction`, …), all 26 name variables (`collection-editor`, `director`, `interviewer`, `illustrator`, `recipient`, `reviewed-author`, `original-author`, `executive-producer`, `series-creator`, …) and the `available-date` date variable. The citation-time variables (`citation-number`, `first-reference-note-number`, `locator`, `year-suffix`) and `custom` stay in `extra`.
  - Validated `Pmid`, `Pmcid` and `Arxiv` brands with `decodePmid`, `decodePmcid` and `decodeArxiv`, and the matching `identifiers.pmid` / `pmcid` / `arxiv` slots. `fromCslJson` reads them from `PMID`, `PMCID` and an `arXiv:` `number` or arxiv.org `URL`, and `toCslJson` writes them back. A `PMID` / `PMCID` that does not validate is dropped, like a bad ISBN.
  - `fromCslJson` reads the legacy aliases `event`, `journalAbbreviation` and `shortTitle` into `event-title`, `container-title-short` and `title-short` when those are absent, and takes optional `RecordLimits` (`maxFieldLength`, `maxAuthors`). `sanitiseText` and `readCslNameArray` take an optional bound.

  **Parsing.** `parseBibliographicFile`, `parseBibtex`, `parseZoteroJson`, `parseCsv` and `parseRis` take optional `ParseOptions`:

  - `mode: "lenient"` keeps every entry without requiring a title or an ISBN or DOI, which a document's bibliography needs. CSL-JSON items are then read in full with `fromCslJson`. The default `"import"` mode keeps the import policy.
  - `maxRecords`, `maxInputLength`, `maxFieldLength` and `maxAuthors` default to today's constants.
  - Breaking: input over the input cap now yields one `{ outcome: "skipped", reason: "too-large" }` instead of `[]`, and entries past the record cap yield one trailing `"truncated"` outcome. Each parser now checks the input cap, not only `parseBibliographicFile`.
  - An entry's key (a BibTeX key, an RIS `ID`, a CSV `key` / `citation key` / `id` column, a CSL-JSON `id` / `citation-key`) is the record's `id` and `citation-key`.
  - BibTeX, RIS and CSV outcomes carry the entry's `position` (`{ offset, line, column }`).
  - `parseBibtex` puts the CSL variables it used to keep in `extra` (`title-short`, `genre`, `keyword`, `event-title`, …) into their typed slots, and an `arxiv` / `pubmed` eprint, `pmid` and `pmcid` into `identifiers`. An eprint or `pmid` that does not validate stays in `extra` as `tex.<field>`.

  **Rich text and dates.** Text variables may carry CSL-JSON's rich-text markup. `parseCslMarkup`, `toCslMarkup` and `stripCslMarkup` read it, write it back and strip it, and `RichText` gains a `NoCase` node (`noCase`). The built-in styles render the markup and sort and dedup on its plain text (`richField` reads markup, the new `plainField` strips it). `issuedYearText` renders a date range's years (`2001–2003`) and a `literal` date. `yearOf` falls back to the year in a `raw` date, and `endYearOf` returns a range's last year.

### Minor Changes

- [#108](https://github.com/thomasfosterau/effect-bib/pull/108) [`1c5a1a3`](https://github.com/thomasfosterau/effect-bib/commit/1c5a1a350598c1d3d58025676a780b28c5028a75) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - BibTeX formatting as CSL markup, and fuller rich rendering. A new opt-in parse option, `bibtexMarkup`, keeps BibTeX's formatting in text fields as CSL rich-text markup (`\emph` / `\textit` → `<i>`, `\textbf` → `<b>`, `\textsc` → small caps, `\textsuperscript` / `\textsubscript` → `<sup>` / `<sub>`, a case-protecting `{DNA}` → `<span class="nocase">`, a literal `<` → `<span class="nocase"><</span>`); without it the output is unchanged. `toHtml` and `toMarkdown` flip-flop italics as citeproc-js does (italic inside italic renders upright: a `font-style:normal` span in HTML), and the Vancouver style renders rich output like APA's, so a title's `<sub>` / `<sup>` / `<i>` reach its HTML; its plain text is unchanged.

- [#90](https://github.com/thomasfosterau/effect-bib/pull/90) [`cf71b88`](https://github.com/thomasfosterau/effect-bib/commit/cf71b88e7ac31c4efeff9544f429f772dba25045) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `parseBibtex` reads BibTeX and BibLaTeX in full: `@string` macros and `#` concatenation (with the predefined month macros), LaTeX decoded to Unicode, BibTeX name rules (particles, `Jr`, braced corporate names as `literal`, `and others`), `crossref` / `xdata` inheritance with BibLaTeX's rules, the BibLaTeX field set (`journaltitle`, `location`, `urldate`, `series`, `edition`, `eprint`, `langid`, …), full `date-parts` from ISO 8601 / EDTF dates, and the BibTeX / BibLaTeX → CSL entry-type mapping Pandoc uses. Fields with no typed slot land in `extra` (CSL variables under their CSL name, the rest as `tex.<field>`). The import policy and `BiblioRecord`'s shape are unchanged, but parsed output changes: grouping braces are removed from values (`{Nested}` → `Nested`), a `von` part is a `dropping-particle` rather than part of the given name, pages read `1-20` for `1--20`, `@booklet` maps to `pamphlet`, and `@xdata` / `@set` entries yield no outcome.

- [#92](https://github.com/thomasfosterau/effect-bib/pull/92) [`e345d0b`](https://github.com/thomasfosterau/effect-bib/commit/e345d0b680bdf03a71e8aae7c72a26e10c73d192) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - In-text citations and rich output. `renderCitations(clusters, records, options)` renders a document's citation clusters and bibliography in one pass: author-date grouping and disambiguation (more names, initials, then year suffixes the bibliography repeats), numeric first-citation numbering with range compression, note-style positions with "ibid.", locators, prefixes and suffixes, narrative citations, and `nocite`. References render to a format-neutral `RichText` AST (italics, links, small caps, …) with `toPlainText`, `toHtml` and `toMarkdown`; `renderReferenceRich` and `RenderedEntry.rich` expose it, and the existing string output is unchanged. Adds `chicagoNotesStyle` (Chicago notes and bibliography), the `note` style category, and optional `CitationStyle.reference` / `citation` and `Locale.ibid` / `locators` members.

- [#18](https://github.com/thomasfosterau/effect-bib/pull/18) [`7ad23bf`](https://github.com/thomasfosterau/effect-bib/commit/7ad23bf097e29004d18c225338bdfb7267ac7119) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Requires `effect@>=4.0.0-rc.118` (the peer range). rc.118 moved the former `effect/unstable/*` modules to top-level paths, so the `./sources` entry imports `effect/http` and its emitted `dist/*.d.ts` reference that path. - [#112](https://github.com/thomasfosterau/effect-bib/pull/112) [`a403681`](https://github.com/thomasfosterau/effect-bib/commit/a403681cdc08f091caa04bea7a7b5f895ef96257) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Embedded web metadata and DOI content negotiation. `readEmbeddedMetadata(html, options?)` reads a web page's citation metadata into records: the page's own record from its Highwire Press `citation_*` tags, schema.org JSON-LD (authors with ORCIDs, the periodical, volume and issue a work is part of) or Dublin Core tags, merged in that order, and one record per COinS span. It is pure and total, scans the page as text in linear time, and bounds the page length and the COinS record count. A record's `URL` is kept only as an absolute `http(s)` link. `ProvenanceSource` gains `"html"` for these records.

  `BiblioLookup` gains `byDoiCsl(doi)`, and `./sources` gains `lookupDoiCsl(client, doi)`: they fetch a DOI's CSL-JSON from `https://doi.org` by content negotiation, which the DOI's registration agency answers (Crossref, DataCite, mEDRA), so DataCite DOIs resolve too. Redirects are followed by hand, only over `https` to a known registration-agency host and at most five deep. `LookupSource` gains `"doi"`. A hand-written implementation of the `BiblioLookup` service must add the new method. Code that switches exhaustively over `ProvenanceSource` or `LookupSource` must handle the new members.

- [#3](https://github.com/thomasfosterau/effect-bib/pull/3) [`1f146f7`](https://github.com/thomasfosterau/effect-bib/commit/1f146f7d78a31faa9b77ec3d6af3840712bf4590) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Initial release, on Effect `4.0.0-rc.118`: the bibliographic toolkit extracted from the website application's `packages/biblio`, with its history.

  `.` (peer: `effect`; no HTTP surface):

  - `BiblioRecord` — a CSL-JSON superset as Effect Schema (closed CSL 1.0.2 item types, name and date variables), with checksummed `identifiers`, a source `provenance` envelope and an `extra` map that passes through CSL keys the model does not consume; `fromCslJson` / `toCslJson` at the interop boundary; the untrusted-text sanitisers.
  - `Isbn` / `Doi` / `Issn` / `Orcid` — branded, checksum-validated identifiers with lenient `decode*` decoders and the ISBN 10 ↔ 13 converters.

  - `scoreMatch` / `isConfidentMatch` / `bestConfidentMatch` — fuzzy same-work scoring over title tokens, author surnames, year and identifiers.
  - `renderReference` / `renderBibliography` — pure `(records, style, locale) → string` with the built-in APA and Vancouver styles.

  `./sources` (peer: `effect`; imports `effect/http`):
