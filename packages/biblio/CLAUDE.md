# `@thomasfosterau/biblio`

The bibliographic toolkit (`packages/biblio`), extracted from the website application's `packages/biblio` with its history. Peer: `effect` only; one dependency, `@thomasfosterau/effect-parse`, whose combinators implement the BibTeX scanner (#72). Two entry points, split so a browser bundle never loads the lookup clients: `.` (pure: `effect` and effect-parse) and `./sources` (`effect/http`).

## Boundary

Imports nothing from this workspace (`.fallowrc.json` zone `biblio`, no outbound rule). `src/sources/*` may import the root modules; the root modules never import `src/sources/*`.

## Invariants

- **`BiblioRecord` is wire-identical to what website persists.** The website application stores records decoded by this schema; any change to a field name, a key's optionality, the brand of an identifier slot or the `provenance` / `extra` shape is a **major**. `fromCslJson` must keep decoding every row it ever produced.
- **The root entry (`.`) never reaches `src/sources/` or a module that sat under `effect/unstable/*` before rc.118.** `.` is the browser-safe half; the HttpClient-backed lookups live behind `./sources` only. The list is `tests/fixtures/forbidden-effect-modules.mjs` (its one home), and a drift test checks it against the installed `effect`. `tests/entry-points.test.ts` walks the source and built import graphs and loads `dist/index.js` with those modules unresolvable. A type-only import counts.
- **Untrusted input never throws.** Every decoder, parser and normaliser is total: `Option.none()`, a `skipped` outcome or a thinner record — never an exception. Free text is clamped (`MAX_TEXT_FIELD_LENGTH`), author lists (`MAX_AUTHORS`), record counts (`MAX_RECORDS`) and input length (`MAX_INPUT_LENGTH`) are bounded — by default; `ParseOptions` / `RecordLimits` let a caller raise or lower each per call, and a bound that is not a positive integer falls back to its default, so no option removes a bound; in BibTeX, so are the distinct fields per entry, the characters macro expansion adds across a document, and the inherited field source decoded across a document (`src/bibtex/`), since macros and `crossref` let a small input reuse one large value many times.
- **Identifiers reach a URL only as brands.** A `decode*` call is the one way in; a source client takes the brand, never the raw string. The service's `byIsbnRecord` / `byDoiRecord` decode first and fail with `InvalidIdentifier` before any request.
- **Rendering is deterministic.** Sorting uses code-unit comparison, never `localeCompare`; styles and locales are data; no network at render time. The golden strings in `tests/render.test.ts` pin the output.
- **The plain-nullable seams stay.** `IsbnForms.isbn10` (what `isbnForms` returns), `parsePersonName`, `cslNameDisplay`, `yearOf`, `makeCslName`, `bestConfidentMatch` and `getStyle` return `null` / `undefined` rather than `Option`: website's `apps/api/src/biblio/*` consumes them as plain nullables, and the shape is a cross-package contract. Each site carries its `oxlint-disable` justification; `effect/prefer-option-over-null` stays at `error` so a new one cannot land silently.
- **The untrusted-input boundary is named.** Inside the package, untrusted values are parsed with `Schema.decodeUnknownOption` (a lenient `Schema.Struct` of `Schema.Unknown` members per upstream object, then one decoder per field) and helpers take the decoded type, never `unknown`. Only the public total decoders take `unknown`, by contract: `sanitiseText`, `sanitiseYear`, `readCslName`, `readCslNameArray` and `fromCslJson`. Each carries its `oxlint-disable effect/no-unknown-parameters` justification; the rule stays at `error`. Lookup tables keyed by upstream strings are `HashMap`s, never object literals, so an inherited key (`constructor`, `toString`) never reads as a mapping.
- **`@since` on every export, `@example` on the entry points.** `vp run -r docgen` compiles and executes every example, so one that fails to type-check or throws is a red gate. State each expected value as an `assert.strictEqual` / `assert.deepStrictEqual` from `node:assert` (imported as `* as assert`), never as a `console.log` with a `// →` comment, which nothing compares (#35): a wrong value then throws and fails docgen. The README's snippets are excerpts of those examples; update both together. Every doc comment opens with a one-sentence summary that stands alone in a hover, in consumer vocabulary (no app paths, no website entity names), as one `/** */` block directly above the declaration — a second block replaces the first in a hover.

## Terms

- **Record** — `BiblioRecord`, a CSL-JSON superset as Effect Schema: the closed CSL 1.0.2 vocabulary (item types, the item `id` and `categories`, and every standard / name / date variable, keyed by its CSL-JSON name) plus three strictly additive members — `identifiers` (branded and validated: the CSL `DOI` / `ISBN` / `ISSN` / `PMID` / `PMCID` variables live here, with `arxiv`), `provenance` (which source, by what retrieval identity) and `extra` (the passthrough map of CSL keys the model does not consume: the citation-time variables, `custom`, unknown keys). `record.ts` lists each variable kind in an object typed by the schema's slots, so a variable added to the schema and not to its list fails to compile.
- **Citation key** — the record's `citation-key` (and `id`), filled from a BibTeX key, an RIS `ID`, a CSV key column or CSL-JSON's own; what a document's citations resolve against.
- **Interop boundary** — `fromCslJson` (lenient, total: any input decodes to a record, hostile input to a thinner one) and `toCslJson` (drops provenance, serialises the brands back into `ISBN` / `DOI` / `ISSN` / `PMID` / `PMCID`, and an arXiv id into an absent `number`, re-merges `extra`). `fromCslJson(toCslJson(record))` lifts a 0.x record's CSL variables out of `extra`.
- **Proven identifier** — an `Isbn` / `Doi` / `Issn` / `Orcid` / `Pmid` / `Pmcid` / `Arxiv`: a branded string that passed its checksum (or, for the schemes without one, its strict syntax) through the lenient `decode*` decoder. The brand is the SSRF / path-injection boundary: an `Isbn` or `Pmid` is exclusively digits, a `Doi` has no control characters, whitespace or `..` segment, and an `Arxiv` is letters, digits, `.`, `-` and at most one `/`, so each is safe to interpolate into an upstream URL path.
- **Outcome** — `ParseOutcome`, one per source entry from the file parsers: `parsed` with a record, or `skipped` with a `SkipReason` (`no-title`, `no-identifier`, `malformed`; `too-large` as the one outcome of an input over the cap, `truncated` as the last after the record cap), with the entry's `SourcePosition` where the format has one (not CSL-JSON). A malformed entry never fails the batch.
- **Parse mode** — `ParseMode`: `import` (the default, the library-import policy: a title and an ISBN or DOI) or `lenient` (every entry is a record; CSL-JSON read in full by `fromCslJson`). The policy is a layer over the same reading, not a separate parser.
- **BibTeX passthrough** — what `parseBibtex` keeps outside the typed slots, in `extra`: any field no mapping consumed as `tex.<field>` (an `eprint` or `pmid` that does not validate included), and the name fields that ended `and others` as `tex.others`. Fields with a CSL variable (`shorttitle` → `title-short`, `type` → `genre`, `keywords` → `keyword`, …) fill it. Only `file` is dropped. The scanner, LaTeX decoder, name parser, dates, inheritance and field mapping live in `src/bibtex/` (internal; not exported from `.`).
- **Match input / score** — `MatchInput` (a title and author display names) and `MatchScore` (title-token Jaccard, author-surname Jaccard as an `Option`, shared significant title tokens); `isConfidentMatch` is the deliberately high-precision same-work decision.
- **Style / locale** — typed data inputs to the render engine (`CitationStyle`, `Locale`); rendering is `(records, style, locale) → string`, pure and network-free. Built-ins: `apaStyle` (author-date), `vancouverStyle` (numeric) and `chicagoNotesStyle` (note).
- **Rich text** — `RichText`, the engine's format-neutral output (an inline AST of text, italic, bold, small caps, super/subscript, `NoCase`, link and display nodes). Styles build it; `toPlainText` is the string output (so the golden strings pin it), `toHtml` / `toMarkdown` the markup. A link renders only for an `http(s)` / `mailto` URL, since a record's URL is untrusted text.
- **CSL markup** — the HTML-like markup CSL-JSON allows in a text variable (`<i>`, `<b>`, `<sup>`, `<sub>`, the small-caps and `nocase` spans). The record keeps it as text; `parseCslMarkup` (in `src/render/markup.ts`, the one reading of it) turns it into `RichText`, anything else tag-like staying literal, and `stripCslMarkup` is its plain text. A style reads a text variable through `richField` (markup kept) or `plainField` (stripped), never `record[key]` raw; sorting and dedup use the plain text.
- **Citation pass** — `renderCitations`: a document's clusters (cites keyed by a caller-chosen id, not a record field) and its bibliography rendered together, because disambiguation, numbering and ibid depend on every citation.
- **Lookup** — `BiblioLookup`, the `Context.Service` over Effect's `HttpClient`: `byIsbnRecord` via OpenLibrary, `byDoiRecord` via Crossref, `byTitle` via OpenAlex. A clean upstream 404 is `Option.none()`; a bad identifier is `InvalidIdentifier`; any other upstream fault is `LookupFailed`.
